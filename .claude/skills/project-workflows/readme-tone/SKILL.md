# README·문서 톤 (존댓말)

`README.md`와 `docs/site/**`는 **딱딱하지 않은 존댓말**로 씁니다. 공문체나 해체(`~한다`, `~둔다`)는 쓰지 않습니다.

`docs/site/`는 GitBook 소스입니다(`.gitbook.yaml`이 루트를 지정). 페이지를 추가하면 `docs/site/SUMMARY.md`에도 등록합니다.

## 종결 어미

| 용도 | 어미 | 예 |
|------|------|-----|
| 설명·소개 | ~합니다 / ~입니다 | 계획표를 생성합니다. |
| 단계 안내 | ~하세요 | `npm run dev`를 실행하세요. |
| 앱이 해 주는 일 | ~둡니다 | 리비전 이력을 남겨 둡니다. |
| 금지·주의 | ~마세요 | 공인 인터넷에 그대로 노출하지 마세요. |
| 결과·상태 | ~됩니다 / ~습니다 | 30분간 사용이 없으면 자동 종료됩니다. |
| 선택 가능 | ~할 수 있습니다 | 권한 모드를 전환할 수 있습니다. |

## 피할 것

- 해체: `~한다`, `~둔다`, `~켠다`, `~읽는다`
- 과도한 공문체: `~하시기 바랍니다`, `~하여야 합니다`, `~하도록 한다`
- 본문 문장에 커밋 메시지형 명사구 종결 남용 (`~반영`, `~추가` — 표·목록 제목은 예외)

## 섹션별 패턴

- **도입 (1~2문장)** — 무엇인지 + 무엇을 하는지. `~합니다`로 마칩니다.
- **사용 절차 (번호 목록)** — 각 단계는 `~하세요`. 부가 설명은 `~됩니다`, `~둡니다`.
- **주의·경고** — `~마세요`, `~않습니다`. 짧게.
- **표의 「동작」·「용도」 열** — 짧은 명사구 허용 (`보드 서버만 켜고 URL 반환`).
- **코드·경로·환경변수** — 백틱 유지. 문장 안 경로는 그대로 두고 주변만 존댓말.

## 적용 순서

1. 해체·공문체 문장을 찾습니다.
2. 위 표에 맞게 **어미만** 바꿉니다. 기술 내용·경로·명령은 건드리지 않습니다.
3. 한 섹션 안에서 어미를 섞지 않습니다 (안내=하세요, 설명=합니다).

## 참고

- 기준 문서: 루트 `README.md`
- 커밋 메시지 톤은 `korean-git-commit`(명사구 종결) — 문서 톤과 혼동하지 않습니다.
- 코드 주석은 이 규칙 대상이 아닙니다(기존 `lib/**` 주석 스타일 유지).
